# OMEGA Messenger

Небольшой E2E-мессенджер на Python: CustomTkinter-клиент, aiohttp-сервер,
гибридное шифрование RSA-OAEP + AES-256-GCM, доверие к ключам по отпечатку (TOFU).

Сервер видит только конверт сообщения (от кого, кому, когда, размер) — текст
расшифровать он не может, приватные ключи остаются у клиентов.

## Быстрый старт (Windows)

**Готовые exe** — папка `dist`:

* `OmegaMessenger.exe` — клиент с меню запуска (умеет поднять сервер рядом);
* `OmegaClient.exe` — «тонкий» клиент без меню: сразу окно входа (эту сборку
  отдают людям, у которых только клиент);
* `OmegaServer.exe` — сервер (консольное окно, порт 8080).

Держите `OmegaMessenger.exe` и `OmegaServer.exe` в одной папке: клиент умеет
поднимать сервер из соседнего файла. При первом запуске Windows может спросить
разрешение брандмауэра — согласитесь, иначе другие устройства не подключатся.

**Готовые комплекты для раздачи** — папка `release`:

* `OMEGA-client.zip` — `OmegaClient.exe` + инструкция для тестировщика;
* `OMEGA-server.zip` — `OmegaServer.exe` + `Запустить-сервер.bat` + инструкция
  для машины-сервера.

**Из исходников:**

1. Двойной клик по `start_messenger.bat` → меню запуска.
2. «Сервер + клиент» — поднимет сервер на `127.0.0.1:8080` и откроет окно клиента.
3. Введите ник → слева список контактов → выберите собеседника → пишите.
4. Кнопка «Ярлык на рабочий стол» создаёт ярлык для запуска одним кликом.

Второй компьютер в той же сети: укажите адрес `ws://<IP-сервера>:8080/ws`
(IP сервер печатает при старте).

Зависимости ставятся автоматически при первом запуске (нужен Python 3.10+),
вручную — `pip install -r requirements.txt`.

## Сборка exe

```bat
build_exe.bat
```

Ставит PyInstaller и собирает `dist\OmegaMessenger.exe`, `dist\OmegaServer.exe`
и `dist\OmegaClient.exe` по спецификациям `OmegaMessenger.spec`,
`OmegaServer.spec` и `OmegaClient.spec`. Сборка one-file: каждый запуск
распаковывается во временную папку (первый старт ~3–5 секунд).
Иконка — `omega.ico`.

## Где разместить сервер

Готовые инструкции и файлы: [deploy/README.md](deploy/README.md) — Render
(бесплатно), Oracle Cloud Always Free, свой ПК с Cloudflare Tunnel, обычный VPS.
Проверка доступности: `python deploy\check_server.py wss://ваш-адрес/ws`.

## Ручной запуск

```bat
python server.py                :: сервер на 0.0.0.0:8080
python client.py                :: окно клиента (ник и адрес спрашиваются при входе)
python Launcher.py              :: меню: сервер / клиент / оба + ярлык
```

Полезные ключи сервера:

```bat
python server.py --port 9000 --host 127.0.0.1
python server.py --list-keys            :: кто закреплён в keyring.json
python server.py --reset-key Егор       :: сбросить ключ ника (после переустановки)
```

Порт также берётся из переменной `PORT` (так делают Render, Railway, Koyeb).

## Интерфейс

Левая панель сверху вниз:

1. логотип **OMEGA** (цвет и стиль выбираются в настройках);
2. поиск по чатам и контактам;
3. вкладки **Чаты | Контакты | Звонки | Настройки**;
4. список: диалоги с последним сообщением, временем и непрочитанными;
   во вкладке «Контакты» — все известные пользователи (● в сети, ○ офлайн);
5. профиль внизу — аватар, ник, статус и шестерёнка настроек.

Область чата: аватар и имя собеседника, статус («в сети», «был(а) 5 мин
назад»), кнопка отпечатка ключа, лента с разделителями дат («Сегодня»,
«Вчера», «7 ноября») и поле ввода.

Настройки (шестерёнка или одноимённая вкладка):

* **Профиль** — аватар (загрузка картинки), ник, статус;
* **Оформление** — пять тем, свои цвета фона и панелей, обои чата
  (файл или ссылка из интернета) с ползунком затемнения, шрифт и его размер,
  стиль логотипа, включение галочек доставки;
* **О программе** — версия, отпечаток вашего ключа, папка данных.

Галочки: `…` — отправляется, `🕓` — в офлайн-очереди, `✓✓` серые —
доставлено, `✓✓` синие — прочитано. Прочтение пока эмулируется на клиенте
(сообщение считается прочитанным, когда собеседник был активен после него):
в протоколе сервера квитанций о прочтении нет.

|---|---|

| `ui_components.py` | виджеты: аватары, логотип, поиск, вкладки, пузыри, лента |
| `theme.py` | темы, шрифты, настройки оформления (`ui_settings.json`) |

| `server.py` | WebSocket-сервер: маршрутизация, офлайн-очередь, каталог ключей |
| `crypto.py` | RSA-OAEP(SHA-256) + AES-256-GCM, отпечатки ключей |
| `trust_store.py` | TOFU-хранилище доверенных ключей (`<ник>_trust.json`) |
| `config.py` | `omega_config.json`, пути к данным (рядом с exe или в %APPDATA%) |
| `Launcher.py` | меню запуска, ярлык, запуск `OmegaServer.exe` в сборке |
| `build_exe.bat`, `*.spec` | сборка exe |

Личные данные рядом с программой: `<ник>_keys.json` (приватный ключ),
`<ник>_history.json` (переписка), `<ник>_trust.json` (доверенные ключи),
`ui_settings.json` (оформление), `avatars/` и `wallpapers/` (картинки),
`keyring.json` (публичные ключи на сервере).

## Как устроено шифрование

1. Клиент генерирует пару RSA-2048, приватный ключ лежит в `<ник>_keys.json`.
2. При входе клиент регистрируется на сервере и публикует открытый ключ.
3. Для каждого сообщения создаётся одноразовый AES-256-ключ: им шифруется текст
   (GCM — с проверкой целостности), а сам ключ шифруется RSA-OAEP открытым ключом
   получателя.
4. Первый ключ собеседника показывается отпечатком — его нужно сверить лично.
   Если ключ потом изменится, клиент покажет предупреждение о возможном MITM.
5. Сервер закрепляет первый ключ за ником (`keyring.json`): войти под чужим ником
   с другим ключом нельзя, пока администратор не сбросит ключ.

Коды: `✓` — доставлено, `⌛` — лежит в офлайн-очереди, `●` — в сети, `○` — офлайн,
`🔒` — ключ подтверждён, `🔓` — ещё не подтверждён.

## Что защищено, а что нет

Защищено: содержимое переписки от сервера и от прослушивания трафика,
целостность сообщений, подмена ключа собеседника после первого контакта.

Не защищено (важно знать):

* **Нет TLS.** Трафик идёт по `ws://` — в локальной сети его можно перехватить и
  подменить. Для интернета нужен `wss://` (nginx + сертификат) или VPN.
* **Ключ не зашифрован паролем.** Кто получил доступ к папке — получил и переписку.
  `<ник>_keys.json` стоит держать только на своём компьютере и не пересылать.
* **Нет прямой секретности.** Если приватный ключ украдут позже, старые сообщения
  (если их сохранили) можно расшифровать.
* **Нет паролей и восстановления аккаунта.** Ник — это просто имя; защита от
  подмены работает только для тех, с кем вы уже сверяли отпечаток.
* **Метаданные видны серверу**: кто кому и когда писал.
* Нет групп, файлов, звонков, редактирования, удалённых сообщений и синхронизации
  истории между устройствами.

## Тесты

```bat
python tests/test_e2e.py
```

Поднимает отдельный сервер на свободном порту с временным `keyring.json`, поэтому
рабочие данные не затрагивает. Проверяет регистрацию, закрепление ключа, вытеснение
старой сессии, доставку онлайн/офлайн, подтверждения и валидацию ввода.
